Method · five phases · three authorities

Proposal, evidence, authorization.

A probabilistic proposal, deterministic evidence about it, and a separate decision. No phase is allowed to do the next phase's job, and no context leaks forward between them.

Scroll to reveal

Phases

Five phases, in order.

01

Initial generation

A raw candidate artifact is produced from design context and an objective. The prompt contains no oracle findings, no prior verdicts and no hints about what the checkers will look for, so the first artifact is a genuine unaided proposal.

02

Independent evaluation

Each deterministic authority checks its own property of that artifact and returns structured findings with rule codes, severity and source lines. The findings are normalised into the common evidence contract, which preserves each authority's meaning instead of averaging the two into one number.

03

Legitimate divergence

The authorities are allowed to disagree, and disagreement is retained as a first-class result rather than resolved away. Collapsing the authorities was one of the compared baselines, and its effect was to suppress the very signal the design exists to expose. The observed divergence.

04

Bounded revision

Revision consumes evidence only, never the model's own assessment. Cycles are bounded and every artifact transformation is hash audited, so the sequence from initial candidate to final candidate can be replayed step by step.

05

Separate verification

VerificationGate issues the only ACCEPT or REJECT in the system. Nothing in the proposal or revision path can produce an acceptance verdict, which is what keeps the loop from grading its own homework.

Authority separation

Stated as prohibitions, because that is what makes them testable.

Proposal

Never decides whether its own output is acceptable, and never sees the findings before writing the first artifact.

Evaluation

Never authors or edits the artifact. Each authority reports on its own property only, and the other authority's verdict is not permitted to stand in for it.

Authorization

Never interprets a successful tool execution as a successful artifact. Execution success and validation are recorded as different things, and only the gate converts collected evidence into a verdict.

The separation rule is recorded in research/architecture/EGER-ARCH-002.md, which is carried as a recommended and not yet validated design.

Evidence contract

One typed artifact, so that two authorities can disagree inside the same schema.

The contract is a pipeline, and the state that moves through it is fixed:

TaskDefinition        >  PromptBuilder      >  ProposalGenerator   (model)
CandidateArtifact     >  OracleAdapter      >  EvidenceNormalizer
EvidenceArtifact      >  RevisionController >  VerificationGate

Hash trio

Input hash, raw evidence hash and evidence hash are stored together with a timestamp that acts as provenance.

An authority that could not answer is recorded as insufficient, not as invalid. The distinction is preserved in the schema because treating an unanswered question as a negative answer would manufacture confidence. Contract source: EGER-EVIDENCE-ORACLE-CONTRACT.

Change control

The architecture was allowed to change. The records were not.

Design changes were made through numbered change records, EGER-CHANGE-001 through EGER-CHANGE-062, each stating what was revised and why. Frozen experimental records were hash pinned and were not rewritten by any tool after the fact, including when later review found something wrong in them.

The repositories holding the evaluation authorities and the gate were kept outside the version control of this project and were not modified by it, so the verdicts in a run cannot have been produced by a tool that changed underneath the run.
