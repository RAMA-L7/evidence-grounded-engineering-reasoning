Reproducibility

Frozen, hashed, re-runnable.

Every verdict on this site is quoted from a frozen artifact rather than re-estimated for the web. This page states the pinned stack, the manifest chain, and the commands that check the implementation.

The pinned stack

Nothing in a run was allowed to move underneath it.

Models

opencode/mimo-v2.5-free and opencode/nemotron-3.5-lightning-free, temperature 0.0, prompts and budgets frozen before the runs

Structural authority

Ṛta 1.5.11@3b5c2f2, executed read only, generation path never invoked on the evidence route

Timing authority

OpenSTA, with the task netlist and library paths supplied by the caller, reporting into the same contract

Gate

VerificationGate unchanged across the reviewed gates, and the only component that emits a verdict

Benchmark

BENCH-002 v0.1, six clean held-out tasks, each with a distinct hash

The authority repositories were kept outside the version control of this project and were not modified by it, so no verdict in a run can have been produced by a tool that changed during the run. Pins and versions are recorded in research/REPRODUCIBILITY.md.

Checking the implementation

The regression suite tests the code, not the findings.

Running the suite verifies that the implementation layer behaves as described. It does not re-derive the results, because the results live in the frozen research records rather than in the test suite. Keeping those two things apart is deliberate.

Worked example

Tracing one number back to its record.

Take the claim that structured evidence activated revision every time it was observed. Here is the chain a reader can walk without asking anyone for anything.

01

Find the claim

It appears on the results page as a headline figure, and is the established rung of the architecture ladder on the findings page. Both places state that it holds under the tested conditions and that activation is not the same as repair.

02

Follow it to the record

The underlying observation comes from the first implementation rung, whose record carries the completion count for the implementation tests. That is the same rung whose status is frozen as established rather than partial.

03

Check the code path yourself

Running the regression suite exercises the implementation that produced the observation. It will not reproduce the finding, because the findings live in the frozen research records and not in the test suite, and the record says so plainly rather than letting the suite stand in for evidence.

One correction is published rather than hidden: an audit pass during preparation removed an unverifiable historical statistic before release. It is described on the limitations page.
